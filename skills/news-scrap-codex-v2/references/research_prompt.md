# Representative Article Research Prompt

대표 기사 선정 후 Codex는 슬라이드 생성 전에 대표 기사에 등장하는 기관, 기업, 기술, 제품, 연구를 추가 리서치한다. 결과는 별도 `featured_research.md`가 아니라 `<work_dir>/news_briefing.md`의 4개 슬라이드 섹션에 반영한다.

## 리서치 원칙

- 기사 원문만으로 부족하면 공식 발표, 기업 제품 페이지, 병원·기관 공지, 논문, 규제·인허가 자료를 우선 확인한다.
- 확인된 사실과 추정되는 내용을 분리한다.
- 출처에서 확인하지 못한 내용은 슬라이드 문안에 넣지 말고 Codex 내부 검토에서 보류한다.
- 내부 점수, 후보 순위, scoring rubric은 쓰지 않는다.
- 각 항목은 Pencil 템플릿의 `bind.*` 자리값으로 들어가므로 짧고 완결된 한국어 문장으로 작성한다.
- 번호가 붙은 반복 항목은 템플릿의 최대 수용 개수다. 조사에서 확인된 만큼만 작성하고, 채울 근거가 없으면 비워 둔다.

## 필수 슬라이드 섹션

아래 제목은 `news_briefing.md`에 그대로 사용한다. `build_pencil_slide_spec_from_md.py`는 이 섹션들이 없으면 실패한다.

```markdown
## 슬라이드 1. 이번 주 대표 기사

## 슬라이드 2. 제품 및 기술 설명

## 슬라이드 3. 회사 및 기관 소개

## 슬라이드 4. 기사 요약
```

## 섹션별 작성 항목

### 슬라이드 1. 이번 주 대표 기사

- 카테고리:
- 기사 제목:
- 부제:
- 요약 본문:
- 핵심 포인트 1:
- 핵심 포인트 2:
- 핵심 포인트 3:

`핵심 포인트`는 최대 3개까지 사용한다. 확인된 포인트가 1~2개뿐이면 나머지는 비워 둔다.

### 슬라이드 2. 제품 및 기술 설명

- 제품·기술:
- 한 줄 소개:
- 설명:
- 작동 단계 1:
- 작동 단계 2:
- 작동 단계 3:
- 기능 1:
- 기능 1 설명:
- 기능 2:
- 기능 2 설명:
- 기능 3:
- 기능 3 설명:
- 기능 4:
- 기능 4 설명:

`작동 단계`는 최대 3개, `기능`은 최대 4개까지 사용한다. 제품 설명에서 확인된 단계나 기능만 작성하고, 없는 항목을 만들지 않는다.

### 슬라이드 3. 회사 및 기관 소개

- 회사·기관:
- 구분 태그:
- 분야 태그:
- 로고 라벨:
- 한 줄 소개:
- 설명:
- 설립:
- 본사:
- 규모:
- 핵심 분야:
- 제품·서비스 1:
- 제품·서비스 1 설명:
- 제품·서비스 2:
- 제품·서비스 2 설명:
- 제품·서비스 3:
- 제품·서비스 3 설명:

`제품·서비스`는 최대 3개까지 사용한다. 대표 기사와 공식 자료에서 확인된 제품·서비스만 작성한다.

### 슬라이드 4. 기사 요약

- 한줄 정리:
- 보충 문장:
- 무엇 제목:
- 무엇 설명:
- 왜 중요 제목:
- 왜 중요 설명:
- 어떻게 제목:
- 어떻게 설명:
- 요약 항목 1 라벨:
- 요약 항목 1 값:
- 요약 항목 1 설명:
- 요약 항목 2 라벨:
- 요약 항목 2 값:
- 요약 항목 2 설명:
- 요약 항목 3 라벨:
- 요약 항목 3 값:
- 요약 항목 3 설명:
- 의료 현장 의미 1:
- 의료 현장 의미 2:
- 의료 현장 의미 3:

`요약 항목`과 `의료 현장 의미`는 각각 최대 3개까지 사용한다. 통계나 숫자가 없으면 억지로 만들지 말고 상태값이나 사실 기반 라벨만 사용한다.

## 작성 기준

- 숫자나 통계가 없으면 억지로 만들지 않는다. `요약 항목 값`은 "발표", "도입", "허가", "연구"처럼 사실 기반 상태값으로 써도 된다.
- 회사의 설립, 본사, 규모처럼 공식 출처에서 확인하지 못한 값은 비워 둔다.
- 빈 항목이 생기면 `apply_pencil_bindings.py`가 해당 반복 카드나 텍스트를 숨기거나 비워 둘 수 있다.
- 반복 항목을 모두 채우기 위해 일반적인 제품 설명, 회사 소개, 추정 효과를 만들어 넣지 않는다.
- 해외 기사도 모든 문구는 자연스러운 한국어로 작성한다.
